# Change: 限定班级范围的知识库检索与内容溯源（迭代 2）

## Why

迭代 1 已经把教研材料与正文入库（`materials` + `knowledge_entries`），并把班级做成了数据边界。
但知识库目前只是"存着"——既不能按内容找，也没有任何可以核对的来源，后续的备课、命题、学情分析无法引用证据。

本迭代补上"能查"：**在本班范围内按内容检索材料正文，并给出可核对的来源（内容溯源）**。
检索是后续所有智能能力的前置条件，因此它与迭代 1 一样，必须先做到"隔离可判定、结果可溯源"，
再往上叠生成式能力。

## What Changes

- 新增**按班级隔离的检索接口**：只在本会话所在班级的正文范围内召回，跨班内容不得出现在结果里。
- 新增**正文分块**：把 `knowledge_entries` 的正文切成带字符区间的块，块是检索的最小单位。
- 新增**向量化与向量存储**：为每个块计算向量并按班级存储，检索用余弦相似度排序。
- 新增**内容溯源**：每条结果必须能指回具体材料与具体片段（材料 id、标题、原始文件名、块序号、字符区间、片段原文）。
- 新增**索引同步与重建**：材料上传成功后立即可检索；提供幂等的重建命令，用于种子数据与历史数据补建索引。
- 新增**前端检索页**：本班检索框、结果列表（片段 + 来源）、点击跳转到材料详情并定位到该片段。
- 新增**评测集**：固定的查询与期望来源，用于判定检索质量与班级隔离是否成立。

## Impact

- 新增能力：`kb-retrieval`（本次为新增，故 delta 只有 `## ADDED Requirements`）
- 受影响数据表：新增 `kb_chunks`（含向量列）；沿用 `materials`、`knowledge_entries`、`classes`、`users`
- 受影响接口：新增 `POST /api/search`；沿用鉴权中间件与会话身份
- 受影响代码：`backend/internal/knowledge`（分块与向量）、`backend/internal/search`（召回与排序）、
  `frontend`（检索页与详情页高亮）、上传路径需同步建索引
- 新增配置：向量维度、分块大小与重叠、检索 `top_k` 上限、单查询长度上限、检索超时
- 性能：单实例、单机 MySQL，检索在配置超时内返回；数据规模按课程场景（材料数百条、正文数十万字）设计

## Non-goals（非目标）

以下条目本迭代明确不做；缺失的"不做"会让实现越界到未评审的范围：

- **生成式问答 / RAG 摘要**：本迭代只做"检索 + 溯源"，不调用大模型生成答案。
- **跨班检索与全局检索**：不提供任何可以绕过班级边界的入口，也不做"教师跨班"的例外。
- **平台超级管理员**：跨班可见会与"只返回本班结果"的验收直接冲突，单独一次变更再设计。
- **重排序模型、查询改写、同义词扩展**：本迭代用单一向量召回 + 余弦相似度。
- **外部向量数据库集群**（Milvus / Qdrant / Weaviate 等）：单实例课程场景不引入额外中间件；向量存于 MySQL。
- **外部 embedding 云服务**：要求可离线复现，密钥与网络依赖都不引入。
- **PDF / Word / 图片解析与 OCR**：材料类型仍限 `.txt` / `.md`。
- **检索历史、个性化推荐、结果收藏与分享**。
- **在线编辑与重新索引的增量调度**：只提供同步索引与幂等重建命令。
