# 1028 个人项目阶段性验收

**交付物**：`个人项目阶段性验收报告.pdf`（11 页）

- `collect_evidence.py`：真实调用平台接口，抓取每次 LLM 调用的完整请求/响应，写入 `evidence.json`
- `build_report.py`：读取 `evidence.json` + 截图，生成 PDF 报告
- `截图/`：7 张真实运行截图（应用列表、对话与引用、原始报文、模板、技能、MCP 工具、工具调用两轮）
- `预览/`：报告前几页的渲染预览

## 五个验证问题的结论

| 问题 | 结论 |
| --- | --- |
| 1. 传给 LLM 的参数 / 返回？模板是否传递？ | 参数为 `model / messages / temperature / max_tokens / stream / tools?`；**模板渲染后原样作为 system + user 消息传递** |
| 2. 绑定知识库是否把全部内容传给 LLM？ | **不会**：只传本班 top-k 命中切片（实测本班 6 个切片，传入 3 个、1100 字） |
| 3. 绑定技能是否包含技能全部内容？ | **包含**：SKILL.md 正文全文注入 system（实测 `cite-check` 237 字） |
| 4. 技能的执行逻辑？ | Skill 是**提示词层面的执行约束**：解析 → 绑定 → 全文注入 system → 模型按规则生成 → 平台把结果与 citations 对齐；不是函数调用（函数调用是 MCP） |
| 5. 集成 MCP 后每次请求的参数？ | 请求多 `tools` 数组（function schema）；第一轮 system+user + tools，模型返回 `tool_calls` 后执行 MCP，第二轮追加 `assistant(tool_calls)` 与 `tool(结果)` |

## 复现

```bash
# 平台运行后
python3 collect_evidence.py     # 生成 evidence.json（真实报文）
python3 build_report.py          # 生成 PDF
```

已校验：11 页、文字层中文可正确提取、排除页脚后文本越界 0 处、6 张截图嵌入。
