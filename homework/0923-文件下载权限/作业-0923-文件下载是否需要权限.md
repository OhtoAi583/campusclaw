# 0923 作业：文件下载是否需要权限？实现逻辑？

**结论：需要权限。** 材料文件不属于"公开静态资源"，下载必须经过服务端鉴权与班级核对；
把上传目录当静态目录暴露（或让前端直接引用文件路径）都算越权漏洞。

本文档说明结论、实现逻辑与实测证据。证据截图见同目录 `截图/`，原始请求记录见 `原始请求记录.txt`。

---

## 一、结论与判定标准

| 场景 | 期望结果 | 实测结果 |
| --- | --- | --- |
| 未登录，直接请求下载接口 | 401，拿不到正文 | 401 `{"error":"unauthorized"}` |
| 未登录，直接猜上传目录静态路径 | 拿不到文件 | 404（该路径不存在） |
| 本班学生，下载本班材料 | 200，拿到正文 | 200，186 字节正文 |
| 本班学生，下载**其他班级**材料 | 拒绝，且不泄露资源是否存在 | 404 `{"error":"not_found"}` |
| 本班学生，下载不存在的 ID | 与跨班**完全同形** | 404 `{"error":"not_found"}`（逐字节一致） |

判定要点：**"下载"这个动作能不能成功，不能由客户端决定，只能由服务端根据会话身份判定。**

---

## 二、为什么不能"不需要权限"

上传目录里的文件如果可直接按路径访问，等价于把材料公开到互联网上，会出现三类问题：

1. **越权下载（BOLA / IDOR）**：知道或猜到文件名/编号就能拿到别的班级的材料。
2. **不可撤销**：文件一旦被 URL 直接引用，即使之后收敛权限，链接仍然有效，无法即时失效。
3. **无法审计**：静态访问不经过应用，日志里没有"谁在什么时候下载了什么"。

课件里对应的是 **Saltzer & Schroeder 的"完全中介"（Complete Mediation）与"默认拒绝"（Fail-Safe Defaults）原则**：
每一次对受保护资源的访问都要重新校验，缺省一律拒绝。

反面做法（本项目明确否决）：
- 把 `uploads/` 挂给 Nginx 当静态目录 —— 静态路径不受会话控制；
- 前端只把"下载按钮"隐藏 —— 只降低可发现性，用 curl 携带 Cookie 改 ID 仍然能绕过；
- 在按 ID 查询时直接用 SQL 过滤掉跨班记录 —— 会退化成"空结果"，无法与"资源不存在"区分。

## 三、实现逻辑

### 3.1 请求链路：只有一条，且信任边界在 Go

```
浏览器 ──▶ web (Nginx) ──▶ api (Go) ──▶ db (MySQL)
              静态资源 + /api 反代     认证 / 授权 / 隔离     用户、材料、会话
```

- Nginx 只托管前端构建产物，并把 `/api` 反代给 Go；**不把上传目录作为静态目录**。
  配置见 `deploy/nginx.conf:40`：

  ```nginx
  # 显式关闭任何试图把上传目录当静态站点的请求。
  location /uploads/ {
      return 404;
  }
  ```

- 浏览器与静态页一律不可信；认证、授权、班级隔离、文件读取全部发生在 Go 进程内。

### 3.2 存储与访问路径：文件只能经接口读取

- 原文件落在 api 容器的上传目录（`UPLOAD_DIR`），只挂给 api；
- 数据库 `materials` 表保存 `stored_name`（服务端生成的随机存储名）、`original_name`（展示用）、`class_id`；
- 读取文件唯一的入口是 `GET /api/materials/{id}/file`。

### 3.3 三层校验（按顺序，任何一层不过就拒绝）

| 层 | 回答的问题 | 失败响应 | 代码位置 |
| --- | --- | --- | --- |
| ① 认证 | 你是谁？会话有效吗？ | **401**，响应体不含标题/正文/路径 | `backend/internal/httpx/httpx.go:60` `RequireAuth` |
| ② 对象级授权 + 班级隔离 | 这条材料属于你所在的班级吗？ | **404**（与不存在同形） | `backend/internal/materials/handlers.go:199` `lookupOwned` |
| ③ 文件读取 | 按服务端存储名打开文件 | 文件缺失也返回 404 | `backend/internal/materials/handlers.go:64` `File` |

**第 ① 层：默认拒绝的鉴权中间件**

```go
// backend/internal/httpx/httpx.go:60
func RequireAuth(next http.Handler, store *auth.SessionStore) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		cookie, err := r.Cookie(CookieName)
		if err != nil { Fail(w, http.StatusUnauthorized, "unauthorized"); return }
		session, err := store.Lookup(r.Context(), cookie.Value)
		if err != nil { Fail(w, http.StatusUnauthorized, "unauthorized"); return }
		next.ServeHTTP(w, r.WithContext(WithSession(r.Context(), session)))
	})
}
```

会话标识存在 `HttpOnly` Cookie 里，服务端 `sessions` 表保存的是它的 **HMAC**（`SESSION_SECRET` 为密钥），
因此即使 `sessions` 表被读走也无法直接冒充用户；`role` 与 `class_id` 每次从 `users` 表读取，
不采信客户端传来的任何身份字段。

**第 ② 层：先取行再核对班级（fetch-then-check）**

关键点是两条读取路径**刻意分开**：

```go
// 列表：隔离条件写死在 SQL 里
// backend/internal/materials/store.go:58
WHERE m.class_id = ?          // 列表路径：直接按会话班级过滤

// 按 ID：不带班级条件，交给上层核对
// backend/internal/materials/store.go:84
WHERE m.id = ?                // 对象路径：先取行
```

```go
// backend/internal/materials/handlers.go:199
func (h *Handler) lookupOwned(w http.ResponseWriter, r *http.Request) (Material, bool) {
	session, ok := httpx.SessionFrom(r.Context())       // 班级只来自会话
	if !ok { httpx.Fail(w, http.StatusUnauthorized, "unauthorized"); return Material{}, false }

	material, err := h.Store.GetByID(r.Context(), id)   // ① 先取行（不带班级过滤）
	if errors.Is(err, ErrNotFound) { notFound(w); return Material{}, false }
	if err != nil { httpx.PermanentFailure(w); return Material{}, false }

	if material.ClassID != session.ClassID {            // ② 再核对班级
		slog.Warn("拒绝跨班访问", "material_id", material.ID, ...)  // 真实原因只写日志
		notFound(w)                                      // 对外与"不存在"完全同形
		return Material{}, false
	}
	return material, true
}
```

**为什么要"先取行"**：如果在 SQL 里提前按班级过滤，跨班访问会变成"查不到 → 空结果"，
既拿不到统一的 404，也没法在服务端日志里区分"越权试探"和"用户输错 ID"。

**第 ③ 层：按服务端存储名读取，且不信任客户端文件名**

```go
// backend/internal/materials/handlers.go:64
func (h *Handler) File(w http.ResponseWriter, r *http.Request) {
	material, ok := h.lookupOwned(w, r)                 // 复用认证 + 班级核对
	if !ok { return }
	path := filepath.Join(h.UploadDir, filepath.Base(material.StoredName))  // 存储名由服务端生成
	file, err := os.Open(path)
	if err != nil { notFound(w); return }               // 文件缺失也不泄露差异
	defer file.Close()
	w.Header().Set("Content-Type", contentTypeFor(material.OriginalName))
	w.Header().Set("Content-Disposition", mime.FormatMediaType("attachment", ...))
	io.Copy(w, file)
}
```

上传时客户端文件名只作为展示标题，存储名由服务端随机生成（`handlers.go:167`），
因此 `../` 一类路径穿越写法不会影响落盘位置。

### 3.4 跨班为什么返回 404 而不是 403

- **403** 等于告诉调用方"这个资源存在，只是你没权限"，可以据此遍历 ID 枚举资源；
- **404** 让"跨班"与"记录不存在"返回**完全相同的状态码与响应体**，不泄漏资源存在性，排障改走服务端日志；
- 因此本项目**统一采用 404，并全文一致**（已写进 README 与 `openspec` 规约 R3.1）。

响应体统一由 `handlers.go:235` 的 `notFound()` 产出，两条路径走同一个函数，天然同形。

1. 未登录访问文件接口 → **401**，响应体不含任何材料标题/正文/路径；
2. 学生访问他班文件 → **404**，且与"ID 不存在"的响应**逐字节一致**；
3. 直接访问上传目录静态路径 → **404**，说明文件没有走静态暴露；
4. 本班文件正常 **200** 下载（`Content-Disposition: attachment`），证明隔离不是"一刀切禁掉下载"。

## 五、设计决策（ADR 摘要）

1. **班级来源**：只从服务端会话（`sessions` → `users.class_id`）得到。
   请求里的 `class_id` 一律忽略，上传落库也用会话班级。
   *备选*：由请求参数指定班级 —— 否决，等于把租户边界交给客户端。
2. **跨班返回 404**（而非 403）：404 隐藏资源存在性，避免 ID 枚举。
   *备选*：403 便于排障 —— 否决作为默认，排障改走服务端审计日志。
3. **上传目录不静态暴露**：文件读取必须经过鉴权接口。
   *备选*：`uploads/` 交给 Nginx 直接服务 —— 否决，静态路径不受会话控制。
4. **上传与入库同事务**：校验在落盘之前完成，事务失败要回滚并删除已写入的文件，
   不留孤儿文件或孤儿记录。*备选*：先写文件再入库 —— 否决，会产生"有文件没记录"的半成品。
