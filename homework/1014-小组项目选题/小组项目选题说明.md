# 小组项目选题说明

**项目题目**：CampusClaw 智能备课与教研协作平台
**副标题**：在班级知识库之上，做「可溯源的备课生成 + 教研审阅 + 学情反馈」
**成员**：龙浩（单人小组）
**文档日期**：2026-10-14

---

## 一、选题背景：为什么继续做 CampusClaw

前两个迭代已经把「底座」做出来了，但它还停留在「能查、能问」，没有进入教师真正的日常工作流：

| 已完成 | 对应迭代 / 任务 |
| --- | --- |
| 登录、角色授权、班级隔离、材料上传与知识库入库 | 迭代 1（已归档 `openspec/specs/auth-upload/`） |
| 限定班级范围的检索、内容溯源（字符区间可回查）、token 认证、基于知识库的问答（带 `[1]` 引用标注） | 迭代 2 + 两次课堂任务（DeepSeek 网关已接入） |

**仍然缺的**：知识库只支持纯文本、检索只有单一向量路径、生成只到「问答」而没有产物、没有协作与审阅、没有审计、单实例部署。

本项目的选题就是把这个底座**往真实教研场景推进一层**：从「能查能问」，做到「能产出可审阅的教研成果，并且每一条结论都能追溯回本班材料」。

## 二、主要功能

功能分四组，标注优先级（P0 必做 / P1 尽量做 / P2 有余力再扩展）。

### A. 知识库能力升级

| 编号 | 功能 | 优先级 | 验收要点 |
| --- | --- | --- | --- |
| A1 | 多格式解析：PDF / Word / PPT 提取正文，扫描件走 OCR | P0 | 解析失败不留残留；原文件与正文分离存储 |
| A2 | 切片策略可选：自动窗口 / 自定义分隔符 / 按 Markdown 标题分章 | P0 | 切换策略可重建索引；切片区间覆盖全文（已有回归测试） |
| A3 | 混合检索：关键字（MySQL ngram 全文）+ 向量（Qdrant）+ RRF 融合排序 | P1 | 两路都必须带班级过滤，回表再核对一次 |
| A4 | 检索评测集与质量门禁 | P0 | 命中率达标 + 隔离用例全部返回空，纳入每次提交检查 |

### B. 智能备课（核心功能）

| 编号 | 功能 | 优先级 | 验收要点 |
| --- | --- | --- | --- |
| B1 | 选定材料范围与课题，生成教案（目标 / 重难点 / 教学流程 / 板书 / 分层作业） | P0 | 每个段落末尾带 `[n]` 引用，指向本班材料的具体切片 |
| B2 | **引用校验**：生成后逐句回查来源，标注「有依据 / 无依据」 | P0 | 无依据句子高亮并可一键重新生成；引用覆盖率作为生成质量指标 |
| B3 | 无依据不生成 | P0 | 检索为空直接返回固定文案，不调用生成模型（沿用课堂任务约定） |
| B4 | 教研模板与风格：按教研组模板输出，可调年级、课时、详略 | P1 | 模板可配置，输出结构可校验 |

### C. 教研协作

| 编号 | 功能 | 优先级 | 验收要点 |
| --- | --- | --- | --- |
| C1 | 教案版本管理与版本对比（diff） | P1 | 每次修改留版本，可回滚、可对比 |
| C2 | 批注与审阅流：教师提交 → 教研组长审核 → 归档 | P1 | 状态机可判定：草稿 / 待审 / 通过 / 退回 |
| C3 | 审计日志：谁、何时、生成了什么、引用了哪些材料 | P1 | 可导出；跨班访问与越权尝试全部留痕 |

### D. 学情反馈（轻量）

| 编号 | 功能 | 优先级 | 验收要点 |
| --- | --- | --- | --- |
| D1 | 作业 / 练习结果录入，按知识点聚合薄弱项 | P2 | 统计口径可复算，不涉个人敏感信息 |
| D2 | 依据学情推荐可复用的本班材料 | P2 | 推荐理由可解释（引用命中的材料） |

**角色扩展**：学生 / 教师 / **教研组长**。教研组长是本项目新增的跨班角色，只对授权的年级组可见，
且每次跨班访问都写审计日志——这是与迭代 1「不做超级管理员」的衔接：先把隔离验收稳定，再用最小权限 + 审计单独设计跨班能力。

## 三、技术方案

### 3.1 架构

```
浏览器（React 18 + TS + Vite）
   │  同源 /api
   ▼
Nginx（静态资源 + 反向代理；上传目录不静态暴露）
   │
   ▼
Go API（net/http，不引入 Web 框架）
   ├── auth 认证与授权 ──── MySQL：users / sessions / refresh_tokens
   ├── kb 解析·切片·向量 ── MySQL：materials / knowledge_entries / kb_chunks
   ├── search 混合检索 ──── Qdrant：向量集合（按 class_id 过滤）
   ├── answer 生成与校验 ── 对话网关（DeepSeek，兼容 OpenAI /chat/completions）
   └── worker 异步任务 ──── Redis：解析 / 重建索引任务队列
                              MinIO：原始文件对象存储（替代本地目录）
```

### 3.2 技术栈

| 层次 | 选型 | 说明 |
| --- | --- | --- |
| 前端 | React 18 + TypeScript + Vite | 沿用；新增教案编辑器与引用侧栏 |
| 后端 | Go + net/http | 沿用；新增 worker 进程（同一代码库，独立 `cmd/`） |
| 关系库 | MySQL 8.0 | 沿用；新增教案、审阅、审计等表 |
| 向量库 | Qdrant | 本课程课件的选型，集合按 `class_id` 过滤；抽取 `VectorStore` 接口便于替换 |
| 缓存 / 队列 | Redis | 文档解析、索引重建等长任务异步化 |
| 对象存储 | MinIO | 原始文件与解析产物分离存放，便于多副本 |
| 模型网关 | DeepSeek（OpenAI 兼容） | 沿用；`ChatClient` 接口已抽象，可换模型 |
| 部署 | Docker Compose（单机） | 沿用；限流状态外置后支持多副本 |
| 规约与流程 | OpenSpec（proposal / design / tasks / delta spec） | 沿用；每个迭代一个 change，五步走（Propose→Review→Apply→Verify→Archive） |

### 3.3 关键设计决策

| 决策 | 选择 | 备选与否决理由 |
| --- | --- | --- |
| 向量存哪里 | 迁移到 Qdrant，保留 `Embedder` / `VectorStore` 接口 | 继续用 MySQL BLOB：数据量与并发上来后相似度计算会拖慢检索；外部向量库的代价是多一个组件，用接口隔离后可随时回退 |
| 生成编排 | 服务端自研编排 | 引入 LangChain / Dify 一类框架：链路被框架黑盒化，无法逐条对照规约验收 |
| 引用可信度 | 服务端句级回查（引用锚点 + 字符区间比对） | 只让模型「自己声明引用」：模型可能编造出处，必须由服务端回查确认 |
| 权限模型 | RBAC + 资源级校验；教研组长跨班需授权范围 + 全量审计 | 直接给管理员全局可见：会破坏「跨班返回 404」的隔离验收，也使越权无法追责 |
| 长任务 | Redis 队列 + 后台 worker | 同步解析大文件：请求超时、失败难恢复；异步的代价是引入任务状态机，需可判定（排队 / 处理中 / 成功 / 失败） |
| 可观测 | 结构化日志 + 指标（检索命中率、生成耗时、引用覆盖率） | 只记原生日志：出问题时无法定位是检索还是生成环节 |

### 3.4 迭代计划（每个迭代一个 OpenSpec change）

| 迭代 | change 主题 | 主要交付 |
| --- | --- | --- |
| 3.1 | 文档解析与切片策略 | 多格式解析、三种切片策略、索引重建、解析失败无残留 |
| 3.2 | 混合检索与评测门禁 | 关键字 + 向量 + RRF、Qdrant 接入、评测集与隔离门禁 |
| 3.3 | 智能备课与引用校验 | 教案生成、句级引用、引用覆盖率、无依据不生成 |
| 3.4 | 协作审阅与审计 | 版本对比、批注、审阅状态机、审计日志与导出 |

### 3.5 质量门禁

- `openspec validate --strict` 通过；每个 change 归档后主力规约更新；
- 单元测试 + 接口级集成测试；关键失败路径（越权、跨班、无依据）必须有负向用例；
- 检索评测集：命中率不低于阈值，**隔离用例必须全部返回空**；
- 第三方按 README 从零可复现（`cp .env.example .env` → `docker compose up --build -d`）。

3. 每个迭代结束做一次自评审清单（Scenario 逐条判定 + 失败路径取证），结论写进迭代说明。

## 五、风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 单人开发，时间与精力有限 | 迭代延期 | 优先级分级（P0 先落地）；每个迭代独立可用、可验收，不做「半成品大功能」 |
| 多格式解析质量不稳定 | 入库正文质量差 | 解析结果与原文分离；解析失败不进索引且不留残留；提供人工复核入口 |
| 向量库引入新组件 | 部署与调试成本上升 | 用 `VectorStore` 接口隔离；Compose 内一键启动；保留 MySQL 方案作为回退路径 |
| 生成内容可能无依据 | 教研成果不可信 | 句级引用 + 服务端回查；引用覆盖率作为门禁指标；无依据不生成 |
| 跨班角色带来隔离风险 | 破坏既有隔离验收 | 教研组长仅在授权年级组内可见，且全量审计；隔离用例必须全过才算通过 |
